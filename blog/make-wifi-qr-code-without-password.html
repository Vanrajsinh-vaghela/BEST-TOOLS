What Is JSON Schema?

JSON Schema is a specification used to describe the expected structure and constraints of JSON data. It can define whether a property is required, which data type it must contain, what values are allowed, and how nested objects or arrays should be structured.

Developers commonly use JSON Schema for REST API validation, request validation, response validation, configuration files, automated testing, documentation and data contracts between services.

Simple JSON Schema Example

{ "$schema": "https://json-schema.org/draft/2020-12/schema","type": "object", "properties": { "userId": { "type": "integer", "minimum": 1 }, "username": { "type": "string", "minLength": 3 }, "email": { "type": "string", "format": "email" }, "active": { "type": "boolean" } }, "required": [ "userId", "username", "email" ], "additionalProperties": false }

JSON Validation vs JSON Schema Validation

Validation Type What It Checks Example Error
JSON Syntax Validation Quotes, brackets, commas, strings and JSON grammar Unexpected token, missing comma
JSON Schema Validation Structure, properties, data types and constraints Missing required property
Type Validation String, number, integer, boolean, array and object types Expected number but received string
Format Validation Email, URI, date-time and other supported formats Invalid email format
Important: Always fix invalid JSON syntax before performing JSON Schema validation. A schema validator cannot properly validate data that is not valid JSON.

Most Important JSON Schema Validation Keywords

Understanding JSON Schema keywords makes it much easier to build reliable API contracts and debug validation errors.

Keyword Purpose Example
type Defines the expected data type "type":"string"
required Defines mandatory properties "required":["email"]
properties Defines object fields and their rules "properties":{"name":...}
additionalProperties Controls unexpected object properties "additionalProperties":false
enum Restricts values to a predefined list "enum":["admin","user"]
minimum Sets minimum numeric value "minimum":0
maximum Sets maximum numeric value "maximum":100
minLength Sets minimum string length "minLength":3
pattern Validates a string using a regular expression "pattern":"^[A-Z]"
format Checks recognized semantic formats "format":"email"

Common JSON Schema Validation Errors

1. Missing Required Property

If the schema contains a required array, every listed property must exist in the JSON object.

"required": ["name", "email", "age"]

If the payload contains only name and email, validation fails because age is missing.

2. Incorrect Data Type

Schema: { "type": "integer" }JSON: { "age": "26" }

The value "26" is a string. If the schema expects an integer, the correct JSON value is 26 without quotation marks.

3. Invalid Enum Value

{ "type": "string", "enum": ["pending", "approved", "rejected"] }

A value such as "processing" fails because it is not included in the allowed values.

4. Unexpected Properties

Using additionalProperties: false can reject fields that are not defined inside the schema. This is useful when an API needs a strict and predictable data contract.

5. Invalid String Format

Schemas can define semantic formats such as email, date-time, and uri, depending on validator support and configuration.

Debugging Tip: When you see a JSON Schema error, inspect the reported property path first. The path usually tells you which object, array or field failed validation.

JSON Schema Draft Versions Explained

JSON Schema has evolved through multiple specification drafts. Different libraries and platforms may support different versions, so always check the documentation of the validator you are using.

Draft General Notes
Draft-04 Older JSON Schema specification still encountered in legacy applications.
Draft-06 Introduced additional schema capabilities and refinements.
Draft-07 Very widely supported and still common in developer tooling.
2019-09 Introduced newer vocabulary and specification improvements.
2020-12 Modern JSON Schema specification with updated vocabulary and behavior.

How to Validate JSON Against JSON Schema

  1. Check JSON syntax first. Make sure the payload contains valid JSON.
  2. Define your schema. Specify properties, required fields and expected data types.
  3. Select the correct schema draft. Make sure your validator supports the chosen draft.
  4. Validate the JSON payload. Run the JSON data through a compatible JSON Schema validator.
  5. Read the validation error path. Identify the exact field or nested object that failed.
  6. Fix the payload. Correct missing properties, wrong types, invalid formats or unsupported values.

JSON Schema Validation for REST APIs

JSON Schema is particularly useful when building REST APIs. A backend can define the expected structure of a request before processing it. This can reduce unexpected data reaching application logic or databases.

Example API Request Schema

{ "$schema": "https://json-schema.org/draft/2020-12/schema","type": "object", "properties": { "productId": { "type": "integer", "minimum": 1 }, "quantity": { "type": "integer", "minimum": 1 }, "currency": { "type": "string", "enum": ["USD", "EUR", "GBP", "INR"] } }, "required": [ "productId", "quantity", "currency" ] }

This type of contract can be useful for API request validation, automated testing, webhook payload verification and communication between microservices.

Validate JSON Schema in JavaScript with Ajv

For Node.js and JavaScript applications, Ajv is a commonly used JSON Schema validator. The basic workflow is to define a schema, compile it and then validate a JSON object.

const Ajv = require("ajv");const ajv = new Ajv(); const schema = { type: "object", properties: { price: { type: "number", minimum: 0 }, inStock: { type: "boolean" } }, required: ["price", "inStock"] }; const validate = ajv.compile(schema); const data = { price: 49.99, inStock: true }; const valid = validate(data); if (!valid) { console.log(validate.errors); } else { console.log("JSON payload is valid."); }

JSON Schema vs TypeScript Types

JSON Schema and TypeScript types can look similar, but they solve different problems. TypeScript primarily provides compile-time type checking inside TypeScript development environments, while JSON Schema can be used to validate actual runtime JSON data.

Feature JSON Schema TypeScript Type
Runtime JSON validation ✅ Yes ❌ Not by itself
Compile-time checking ❌ No ✅ Yes
API contracts ✅ Excellent ⚠️ Requires additional tooling
Required properties ✅ Supported ✅ Supported
Works outside JavaScript ✅ Yes ❌ TypeScript-specific

JSON Schema Validation Best Practices

  • Keep schemas versioned alongside your API contracts.
  • Use clear property names and consistent data types.
  • Define required fields only when they are genuinely mandatory.
  • Use enum when a field accepts a controlled set of values.
  • Use numeric constraints such as minimum and maximum where appropriate.
  • Use string constraints such as minLength, maxLength and pattern carefully.
  • Test valid and invalid payloads automatically.
  • Check which JSON Schema draft your validation library supports.

Frequently Asked Questions

What is a JSON Schema validator?

A JSON Schema validator is software that compares JSON data against a JSON Schema and reports whether the payload follows the defined structure and constraints.

Can I validate JSON Schema online?

Yes. Online JSON Schema validator tools can check JSON payloads against a schema. For syntax problems, you can first use the BestTools JSON Formatter to format and inspect the JSON.

What is the difference between JSON Schema and JSON validation?

JSON validation can refer to checking whether a string is valid JSON syntax. JSON Schema validation checks whether valid JSON follows a predefined contract, including properties, data types, required fields and constraints.

Can JSON Schema validate nested objects?

Yes. JSON Schema supports nested objects and arrays, allowing developers to define validation rules for deeply structured API payloads.

Can JSON Schema validate arrays?

Yes. You can use the type and items keywords to define the expected array structure and the type or schema of each item.

Why does my JSON Schema validation fail even though the JSON is valid?

Valid JSON syntax only means that the JSON grammar is correct. The payload can still fail schema validation because a required property is missing, a value has the wrong type, an enum value is unsupported or another schema constraint is violated.
