What Does “Unexpected Token in JSON” Mean?

JavaScript throws an Unexpected token in JSON error when a JSON parser encounters a character or value that is not valid according to JSON syntax. The error commonly appears when using JSON.parse() or when an application expects an API response to contain JSON.

For example, this is valid JSON:

{ "name": "Alice", "age": 25, "active": true }

But this is not valid JSON because the property name and string value use single quotes:

{'name': 'Alice'}

Standard JSON requires double quotes around property names and string values.

Why Does “Unexpected Token” Happen at Position 0?

The position number represents the character index where parsing failed. Position 0 means the parser failed immediately at the first character.

Example Error Typical Meaning
Unexpected token < in JSON at position 0 The server probably returned HTML instead of JSON.
Unexpected token o in JSON at position 1 The input may already be a JavaScript object or may not be valid JSON text.
Unexpected token } in JSON at position N A closing bracket or object structure is probably malformed.
Unexpected end of JSON input The JSON is incomplete, truncated or empty.

7 Common Causes of JSON Parse Errors

1. API Returns HTML Instead of JSON

One of the most common causes of Unexpected token < in JSON at position 0 is an API endpoint returning an HTML error page.

If the response begins with:

<!DOCTYPE html> <html> <head>...

it is not JSON. It may be a 404 page, server error page, login page or redirect response.

Fix: Check the API URL, HTTP status code, response headers and actual response body before calling response.json().

2. Single Quotes Instead of Double Quotes

JSON does not use JavaScript-style single-quoted strings.

❌ Invalid: {'name': 'John'}✅ Valid: {"name": "John"}

3. Trailing Commas

A trailing comma after the final property or array item is invalid in standard JSON.

❌ Invalid: { "name": "John", }✅ Valid: { "name": "John" }

4. Unquoted Object Keys

❌ Invalid: {name: "John"}✅ Valid: {"name": "John"}

5. Empty or Incomplete JSON Response

If your server returns an empty response but your application attempts to parse it as JSON, you may see Unexpected end of JSON input.

6. Broken Strings and Escape Characters

Quotes inside strings must be escaped correctly. Invalid line breaks and backslashes can also break JSON parsing.

❌ Invalid: {"message":"He said "hello""}✅ Valid: {"message":"He said "hello""}

7. Wrong Content Returned by the Server

Your application may expect JSON while the server returns plain text, XML, HTML, a redirect page or an authentication response.

How to Fix “Unexpected Token < in JSON at Position 0”

This particular error deserves special attention because it frequently happens with JavaScript fetch() requests.

Instead of immediately calling response.json(), inspect the response:

const response = await fetch("/api/data");console.log("Status:", response.status); console.log("Content-Type:", response.headers.get("content-type")); const text = await response.text(); console.log("Server response:", text);

If the console shows HTML instead of JSON, the JSON parser is not the real problem. The API endpoint or server response needs to be fixed first.

How to Debug JSON Errors With fetch()

When using a REST API or JavaScript fetch request, first check whether the HTTP request succeeded before assuming that the body contains valid JSON.

async function loadData() {try { const response = await fetch("/api/data"); if (!response.ok) { throw new Error( `HTTP error: ${response.status}` ); } const contentType = response.headers.get("content-type") || ""; if (!contentType.includes("application/json")) { throw new Error( "Server did not return JSON." ); } const data = await response.json(); console.log(data); } catch (error) { console.error( "JSON/API error:", error.message ); } }

How to Safely Use JSON.parse()

If JSON comes from a user, API, local storage or another external source, wrap parsing in try...catch so malformed data does not crash your application.

function parseJSONSafely(value) {try { return JSON.parse(value); } catch (error) { console.error( "Invalid JSON:", error.message ); return null; } }

JSON Error Checklist

  • Are all object keys wrapped in double quotes?
  • Are all string values wrapped in double quotes?
  • Did you remove trailing commas?
  • Are brackets and braces properly matched?
  • Are booleans written as true or false?
  • Is null written as null?
  • Does the API actually return JSON?
  • Is the HTTP response status successful?
  • Is the response empty?
  • Does the response contain an HTML error page?
  • Are strings containing quotes properly escaped?

Frequently Asked Questions

What does Unexpected token in JSON at position 0 mean?

It means the JSON parser encountered an invalid character at the beginning of the input. A common example is an API returning HTML instead of JSON.

Why does fetch().json() give Unexpected token <?

The < character commonly indicates that the server returned HTML, such as a 404 page, login page or server error, instead of JSON.

Can JSON use single quotes?

No. Standard JSON strings and property names use double quotes. Single quotes are not valid JSON syntax.

Are trailing commas allowed in JSON?

No. Standard JSON does not allow a comma after the final property in an object or after the final element in an array.

What does Unexpected end of JSON input mean?

It usually means that the JSON input ended before the parser found a complete valid JSON value. An empty or truncated response can cause this error.

How do I find the exact JSON error position?

The position number identifies the character index where parsing failed. You can inspect the raw response in your browser developer tools or use the BestTools JSON Formatter to make the structure easier to inspect.
